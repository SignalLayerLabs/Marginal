# MARGINAL Marketing Refactor — Design Specification

## Goal
Make MARGINAL understandable in five seconds and compelling enough to earn GitHub stars without overstating unproven performance claims.

## Positioning
Primary category: **runtime governor for AI coding agents**. Primary problem: **AI agents can repeat work without making progress**. Primary promise: **MARGINAL detects no-progress repetition**. Primary differentiator: **MARGINAL starts by observing and must earn limited enforcement authority from evidence.**

Canonical message stack:
1. **AI agents repeat work that changed nothing.**
2. **MARGINAL catches it.**
3. **Observe first. Prove waste. Earn enforcement.**

## Experience hierarchy
Hero → deterministic mechanism demo → How it works → Integrations → Proof → Research → FAQ → Install CTA.

## Claim discipline
- Never claim the historical 24.93% token delta was caused by MARGINAL.
- State the smoke was 0/3 vs 0/3 and no deny was applied.
- Label the deterministic visual demo as not a production benchmark.
- Codex is Tool Enforcement, never Full Compute Enforcement.
- Claude Code, OpenCode and PrivacyCode are Observe-only.

## SEO
One H1; canonical `https://signallayerlabs.github.io/Marginal/`; intent-focused title/description; OG/Twitter 1200×630 image; SoftwareApplication + FAQPage JSON-LD; semantic sections; robots.txt and sitemap.xml.

## Visual language
Dark technical canvas, acid-green action accent, red only for waste, mono trace labels, strong contrast, responsive panels, no external font dependency, motion disabled under prefers-reduced-motion.
