# Interactive Killer Demo Design

## Goal

Turn `/demo/` from a marketing page into an executable browser race that lets a visitor watch the same deterministic coding task unfold simultaneously with and without MARGINAL.

## Core experience

The page opens on one aggressive proposition: **SAME BUG. SAME START. WATCH THE EXTRA WORK.** The visitor presses **RUN THE SAME TASK**. Two synchronized lanes then process the same candidate action at the same tick:

- **WITHOUT MARGINAL** executes every candidate.
- **WITH MARGINAL** evaluates that same candidate and either `FUND + EXECUTE` or `REJECT BEFORE SPEND` according to the committed deterministic Killer Demo result.

The visitor can Play/Pause, advance one step, Reset, and switch playback speed. Both lanes expose live terminal output, stage, workspace state, calls, declared tokens, estimated USD, and the current MARGINAL decision reason. The run ends only when both lanes display the same verifier `PASS`, followed by a high-contrast comparison of total work.

## Truth model

The race is a deterministic replay of `run_killer_demo()` artifacts. Candidate names, selected actions, decision reasons, scores, expected gains, declared tokens, estimated USD, outputs, and final outcome come from the result data generated by MARGINAL. Browser timing is accelerated and explicitly labeled as playback timing, not provider telemetry. The page must not imply that declared demo estimates are production savings.

## Architecture

`src/marginal/killer_demo.py` remains the source of truth. It generates:

- `index.html`: semantic race shell and embedded JSON playback payload.
- `demo.css`: visual system and responsive split-screen race.
- `demo.js`: deterministic playback state machine and controls.
- existing `result.json`, `trace.jsonl`, `RESULTS.md`, and `comparison.svg` artifacts.

The generated JS does not fetch a backend, use an API key, call an LLM, or invent data. GitHub Pages remains static and copies the complete `demos/killer-demo/` directory.

## Marketing requirements

- First screen is the race, not an explanation page.
- Primary CTA: `RUN THE SAME TASK`.
- Headline: `SAME BUG. SAME START. WATCH THE EXTRA WORK.`
- Visible labels: `WITHOUT MARGINAL`, `WITH MARGINAL`, `EXECUTE EVERYTHING`, `DECIDE BEFORE SPEND`.
- The waste gap grows visually as MARGINAL rejects higher-cost actions.
- Final reveal emphasizes same verified outcome and the exact deterministic totals.
- Methodology and disclaimers are secondary, below the race.

## Interaction requirements

- Run / Pause / Next step / Reset.
- Speed selector: 0.5x, 1x, 2x, 4x.
- Synchronized tick counter and Diagnose -> Fix -> Verify stage rail.
- Keyboard: Space toggles playback, ArrowRight advances, R resets when focus is not in a form control.
- `prefers-reduced-motion` disables decorative animation while preserving functionality.
- Responsive mobile layout stacks lanes without hiding data.

## Compatibility requirements

Existing Killer Demo tests must continue to find their historical publication-contract strings. Preserve those strings in a hidden legacy contract block rather than letting legacy copy drive the visual experience.

## Verification requirements

- New tests validate playback payload shape, 9 synchronized candidate ticks, 3 funded actions, external CSS/JS generation, control surface, and artifact reproducibility.
- Existing `tests/test_killer_demo.py` remains green.
- `ruff format --check .`, `ruff check .`, Codex runtime provenance check, targeted plugin tests, full pytest, JS syntax check, and `git diff --check` must pass locally before push.
